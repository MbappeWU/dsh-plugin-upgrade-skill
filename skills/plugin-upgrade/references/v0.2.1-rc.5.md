### DSH-0.2.1-R4-01 · Cosmetic release: one thinking-content display improvement in the notes, zero plugin-facing package changes

- **Type**: fix
- **Applies to**: every plugin — the compatibility ledger can add `0.2.1-rc.5` with no code review; plugins pinning exact `@deepseek-ai/*` subpackage versions (rare) must widen or bump their pins
- **Touchpoints**: #0 (install surface — version pins only), #1–#9 (no plugin-facing service, slot, event, or UI contract changes)
- **Action level**: informational
- **Symptoms**:
  - The upstream release notes for `dsh-v0.2.1-rc.5` list a single change: "Improve how thinking content is displayed in conversations" (@LegGasai) — a host/web UI cosmetic change with no API coordinates.
  - First-hand npm pack diff (2026-10-30): the CLI package's file list is identical to rc.4 and exactly one file differs — `package.json` (the `version` field plus every internal `@deepseek-ai/dsh-*` dependency pin moved rc.4 → rc.5). The `lib/` bundle is byte-identical.
  - Spot-checked subpackages `dsh-plugin-manager`, `dsh-web-app`, and `dsh-web-frontend` (the GUI asset carrier) each diff to rc.4 **only** in `package.json`, and every differing line is a version pin; the frontend hash bundle that canvas/webview plugins render inside is unchanged.
  - The notes' thinking-display improvement therefore ships in workspace packages outside the CLI tarball's carried bundle; it does not surface as a plugin contract change in anything the CLI or the spot-checked GUI carrier exposes.
- **Migration recipe**:
  1. Add `0.2.1-rc.5` to the plugin's `compatibility.json` dsh list and cut a declaration release — no code change, no re-review of touchpoints.
  2. If (unusually) a plugin declares a dependency on a specific `@deepseek-ai/dsh-*` subpackage version, either widen the range or move the pin to `0.2.1-rc.5`; the APIs behind those pins did not change.
- **Verification**: run the plugin's smoke surface (panel open, one game/tool round-trip) under rc.5 — output must be indistinguishable from rc.4; a diff here indicates an environment problem, not a host change.
- **Source**: primary — the upstream [release `dsh-v0.2.1-rc.5`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.5) (notes: one thinking-content display improvement) and the published packages themselves: [`@deepseek-ai/dsh@0.2.1-rc.5`](https://www.npmjs.com/package/@deepseek-ai/dsh/v/0.2.1-rc.5) plus the rc.5 builds of [`dsh-plugin-manager`](https://www.npmjs.com/package/@deepseek-ai/dsh-plugin-manager/v/0.2.1-rc.5), [`dsh-web-app`](https://www.npmjs.com/package/@deepseek-ai/dsh-web-app/v/0.2.1-rc.5), and [`dsh-web-frontend`](https://www.npmjs.com/package/@deepseek-ai/dsh-web-frontend/v/0.2.1-rc.5); first-hand npm pack diff (2026-10-30): CLI `lib/` byte-identical to rc.4, all spot-checked subpackage diffs limited to `package.json` version pins.
- **Field note** (first-hand, 2026-10-30): this card was cut **without installing rc.5** — the working machine already runs the newer `0.2.2-alpha.2` from the 0.2.2 corridor, so the evidence is the package diff and release notes above rather than a live session; deployments that do install rc.5 should re-run the smoke surface as in Verification before cutting declarations.
